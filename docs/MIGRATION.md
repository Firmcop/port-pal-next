# Port Pal 2.0 — migration from Vite/Lovable to Next.js

## What changed

| Area | Before (v1) | After (v2.0) |
|---|---|---|
| Framework | Vite 5 SPA, React 18, react-router 6 | Next.js 16 App Router, React 19 |
| Code loading | All 177 routes in one 4.2 MB bundle | One lazy chunk per screen; shared shell ≈1.0 MB |
| Auth gate | Client-side, after the whole bundle loads | `src/proxy.ts` redirects on the server; client shell keeps onboarding/paywall checks |
| Session storage | `localStorage` (Lovable preview broker) | Cookies via `@supabase/ssr`, readable by server code |
| Data caching | React Query defaults (refetch on every focus) | 30 s stale time, no refetch-on-focus; realtime invalidation unchanged |
| AI / MCP | `@lovable.dev/mcp-js`, 6 tools, 3 broken | `@modelcontextprotocol/sdk` at `/api/mcp`, 19 read-only tools, unit-tested |
| Build tooling | `lovable-tagger`, Lovable Cloud env | Plain npm; deploy anywhere Next.js runs (Vercel, Netlify, Docker) |
| Env vars | `VITE_*` | `NEXT_PUBLIC_*` (see `.env.example`) |
| Tests | 140 / 145 passing | 150 / 150 passing |

Database, migrations, RLS policies, RPCs and edge functions are untouched.

## Measured speed (login page, production builds)

Chromium, 1.6 Mbps down / 150 ms RTT, 4× CPU slowdown:

| | v1 | v2.0 |
|---|---|---|
| JavaScript downloaded | 4,167 KB (1,048 KB gzip) | 967 KB (289 KB gzip) |
| Largest contentful paint | 7.4 s | 0.8–0.95 s |
| Load event | 7.4 s | 2.1 s |

## Mechanical changes made to the screens

- `src/pages` → `src/views` (Next.js reserves `pages/`).
- `import … from "react-router-dom"` → `import … from "@/lib/router"` (compatibility layer over `next/navigation`).
- `import.meta.env.VITE_X` → `process.env.NEXT_PUBLIC_X`.
- `VendorDepotDetail` reads the org id from the `id` route param (Next.js requires one slug name per level).
- `/paywall` is now a real route (it was linked from `RequireModule` but fell through to 404).
- `/.lovable/oauth/consent` moved to `/oauth/consent`; the old path is rewritten so existing config keeps working.
- Removed: `src/App.tsx`, `src/main.tsx`, `index.html`, `vite.config.ts`, the Lovable preview auth broker, and unused `App.css`.

## Cut-over checklist

1. Create the hosting project (e.g. Vercel) from this repo; set `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `NEXT_PUBLIC_SUPABASE_PROJECT_ID`, `NEXT_PUBLIC_SITE_URL`.
2. Supabase → Auth → URL configuration: add the staging and production URLs to Site URL / Redirect URLs (password reset and invites link back here).
3. Supabase → Auth → OAuth server: set the consent URL to `https://<domain>/oauth/consent`.
4. Smoke-test on staging with one user per role: staff admin, accountant, gate clerk, portal customer, platform admin.
5. Move `portal.firmcop.com` DNS to the new host. Everyone signs in once (session storage moved to cookies).
6. Rollback = point DNS back; both builds share the same database.

## Known follow-ups

- The legacy Supabase edge function `supabase/functions/mcp` (generated by Lovable) still exists; once AI clients point at `/api/mcp` it can be deleted.
- Screens still render client-side (`ssr: false`). Phase 2 converts the busiest ones to Server Components.
- The shared shell still carries all five i18n locales; loading them per language would cut roughly another 100 KB.
